# NetworkAccess

This directory contains common [AutoREST.PowerShell](https://github.com/Azure/autorest.powershell) configurations for NetworkAccess v1.0 and/or beta modules.

## AutoRest Configuration

> see <https://aka.ms/autorest>

``` yaml

```

### Directives

> see https://github.com/Azure/autorest/blob/master/docs/powershell/directives.md

Reviewed v3 migration: only this shared file is in scope. The beta profile is
required; v1.0 is explicitly excluded, not an assertion of API-operation absence.
Profile-local readmes and `src/readme.graph.md` are ignored.
The evidence ledger is `wrapper/NetworkAccess_directiveMigrationMap.json`;
`NetworkAccessDirectiveMigrationTests` pins the exact suppression and unaffected
neighbors. Structural naming supplies the published forwarding-rule noun.
Three distinct linked-policy GETs use source-backed `PolicyLinkPolicy` nouns:
the parent returns `networkaccess.policyLink`, while its `/policy` navigation
returns `networkaccess.policy` with the same mandatory IDs. Ordinary List/Get
names and default URLs are unchanged; no selector or variant group is introduced.
Parameter aliases/transforms and schema/response directives remain Deferred;
the active AutoRest directives below are retained.

``` yaml
directive:
# Rename headers parameter provided in the open api file to avoid conflict with existing header property generated by Autorest for custom header support.
# v3 directive 1: DeferredParameter; do not implement the Headers rename here.
  - where:
      verb: New
      subject: ^NetworkAccessLogTraffic$
      variant: CreateExpanded
      parameter-name: Headers
    set:
      parameter-name: AccessHeaders
# v3 directive 2: DeferredParameter; do not implement the Headers rename here.
  - where:
      verb: Update
      subject: ^NetworkAccessLogTraffic$
      variant: ^(UpdateExpanded|UpdateViaIdentityExpanded)$
      parameter-name: Headers
    set:
      parameter-name: AccessHeaders
# Parameter BodyParameter has multiple parameter types. 
# v3 directive 3: Mapped; suppress only PATCH on the forwarding policyRules item.
# GET/DELETE, collection POST, the parent policy PATCH, and other policy families remain.
  - where:
      verb: Update
      subject: ^NetworkAccessForwardingPolicyRule$
    remove: true
```
